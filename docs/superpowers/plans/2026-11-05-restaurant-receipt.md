# 식당 접수 API 구현 계획

요구: 기존 NestJS/로컬 DB에서 자사 주문 목록 조회, 주문 수락(식당 확정 조리시간), 거절.
범위: 기존 reserve_cooking/close_pickup_order를 트랜잭션으로 재사용. 실제 SDK ETA와 물리적 픽업 공간 예약은 미연결임을 명시. 수락 입력의 eta.source=MOCK만 허용한다.

- [x] HTTP 테스트: 목록/권한, 수락·예약, 거절, 입력/ETA 누락, 버전충돌, 동일 키 재전송/변경 본문, 경쟁 요청과 실패 시 롤백.
- [x] 최소 접수 작업 이력 마이그레이션: 사용자·주문·동작·requestKey 고유성, 요청 해시·요청·응답 저장, RLS 및 서버 전용 접근.
- [x] 기존 상태·식당/주문 잠금 순서 유지, 권한 확인 후 재전송→상태/버전→DB 처리→이력 저장을 원자 실행.
- [x] 공통 응답에 version/확정 조리시간/조리 예약/ETA 출처를 추가. 목록 페이지 구분·상태 필터 검증.
- [x] 실행/형식검사/기존 API·DB 회귀 검증, 접수 계약과 한계 문서화, 최종 검토.

기존 마이그레이션을 편집하지 않고 신규 파일만 추가. 신규 패키지는 도입하지 않는다.

## 검증·검토 기록
- 최초 접수 HTTP 테스트는 미구현 경로 404로 실패(RED).
- 구현 후 기존 전체 API/DB 테스트 통과.
- 최종 검토에서 거절 사유가 후속 GET/목록에 누락됨을 발견. 회귀 테스트에서 undefined를 재현한 뒤 공통 응답에 이력 조회를 추가했다.
- 재시작 후 동일 수락 요청이 원래 응답을 반환하고 예약이 하나만 남는 테스트 추가.
- 웹/서버 빌드·타입 검사·연결 스모크 통과. 새 의존성 없음. 기존 SQL 마이그레이션은 편집하지 않고 작업 이력 테이블 마이그레이션만 추가.
- 결정: 로컬 시연 ETA의 관측 유효기간은 5분, 미래 허용 오차 30초. 실제 차량 ETA 수신은 후속 작업.
- 한계: 물리적 픽업 공간 확정은 수행하지 않으며 응답에 NOT_IMPLEMENTED로 명시. 독립 PostgreSQL 연결 경쟁 검증은 수행하지 않음.
